# 测试网证据包规范

本规范描述 `--evidence-out` 生成的测试网证据包。证据包只用于 `Binance Spot Testnet / BTCUSDT / 4h` 闭环复核，不用于实盘启动。

## Schema

当前 schema：

```text
kxian.testnet.evidence.v1
```

必填顶层字段：

- `schema`
- `schema_version`
- `generated_at`
- `command`
- `scope`
- `credentials`
- `profile`
- `observations`
- `launch_checklist`
- `result`
- `audit`
- `acceptance`
- `redaction`
- `safety`

证据包不允许额外顶层字段。新增字段必须先补充规范与测试。

## 固定范围

`scope` 必须固定为：

```json
{
  "mode": "testnet",
  "exchange": "binance",
  "symbol": "BTCUSDT",
  "interval": "4h",
  "use_testnet": true
}
```

同时必须保持：

- `allow_live=false`
- `enable_live_autotrade=false`
- `live_confirmation_present=false`

## 凭证规则

`credentials.present` 只能保存 boolean：

```json
{
  "binance_api_key": true,
  "binance_api_secret": true
}
```

禁止写入：

- API key 原文或片段
- API secret 原文或片段
- `X-MBX-APIKEY`
- `Authorization`
- query `signature`
- HTTP header 原文
- 完整异常上下文里的敏感字段

## 审计字段

`audit` 用于复核证据生成环境和契约状态，必须包含：

- `git_commit`：当前仓库提交 SHA；本地非 Git 环境可为 `unknown`。
- `dirty_worktree`：生成证据时工作区是否存在未提交修改；本地非 Git 环境可为 `unknown`。
- `command_context.command`：生成证据的 CLI 或 Dashboard 命令名。
- `command_context.profile_key`：固定为 `testnet:binance:BTCUSDT:4h`。
- `command_context.mode/exchange/symbol/interval/use_testnet`：必须与测试网闭环范围一致。
- `command_context.result_status` 与 `result_reason`：记录本次命令结果摘要。
- `command_context.launch_checklist_status` 与 `launch_checklist_phase`：记录 checklist 摘要。
- `schema_validation`：由 `testnet_evidence_contract_failures` 生成，包含 `status`、`validator`、`failure_count`、`failures`。
- `content_sha256`：对脱敏证据包的规范化 JSON 做 SHA-256，计算时排除 `audit.content_sha256` 自身。

`schema_validation.status=pass` 时，`failure_count` 必须为 `0` 且 `failures` 必须为空数组。`content_sha256` 必须是 64 位十六进制字符串，并能被重新计算校验。

### `dirty_worktree` 判定

| 值 | 含义 | 继续条件 |
| --- | --- | --- |
| `false` | 证据生成时工作区干净 | 可作为正式证据使用 |
| `true` | 证据生成时存在未提交修改 | 需要记录原因；正式验收前应提交后重新导出 |
| `unknown` | 当前环境无法执行 Git 状态检查 | 只能作为临时诊断，不能当作干净证据 |

## Secret Scan 边界

CI 会阻断已跟踪的 `.env`、`.env.*`、`.envrc`、`.npmrc`、`.pypirc`、`.netrc`、SSH 私钥名、证书容器、Terraform 状态或变量、云服务账号 JSON、数据库文件、`data/`、`artifacts/` 等运行态文件。模板文件 `.env.example` 与 `.env.testnet.example` 允许提交，因为它们不应包含真实凭证。

高置信内容扫描会覆盖常见 AWS key、Slack token 与私钥头部。该扫描不是万能密钥识别器，提交前仍必须人工确认没有真实 API key、secret、cookie、token、签名或账户私密信息。

## 验收字段

`acceptance` 必须包含：

- `required_status=pass`
- `required_phase=testnet_observed_ready_for_live_review`
- `ready_for_live_review`
- `live_ready=false`

`ready_for_live_review=true` 只表示可以进入人工 live review，不表示可以启动 live。

## 安全字段

`safety` 中所有布尔值必须为 `false`：

- `live_promote_executed=false`
- `live_loop_executed=false`
- `live_checklist_required=false`
- `production_credentials_allowed=false`

如果任一字段为 `true`，证据包不合格。

## 观察摘要

`observations.non_ordering` 和 `observations.bounded_order` 应保留摘要信息：

- `observation_id`
- `execute_loop`
- `cycles_completed`
- `failures`
- `latest_reason`
- `order_lifecycle`
- `account`
- `fill_sync`
- `preflight`
- `open_order_count`

不保存完整 HTTP 请求、完整响应 header 或未脱敏异常文本。

## 校验

代码中使用 `testnet_evidence_contract_failures` 校验：

- schema 是否正确
- 顶层字段是否完整且无额外字段
- 范围是否固定为测试网闭环
- 凭证存在状态是否为 boolean
- `audit` 的命令上下文、schema 校验结果和内容哈希是否合格
- live 安全字段是否全部为 `false`

测试覆盖：

- 敏感字段名脱敏
- 普通文本中夹带密钥值脱敏
- header、authorization、signature 脱敏
- schema 白名单
- audit 字段契约
- live 越界字段拒绝
