# 实盘灰度操作手册

本手册只覆盖从“测试网已闭环”进入“实盘小额灰度”的人工准入流程。目标不是直接长期自动交易，而是先证明生产 API、实盘 profile、端点、订单生命周期、成交同步、账户同步和回退动作都可控。

## 安全边界

- 不要复用 Binance Spot Testnet key。生产 key 必须单独创建，禁用提现，只开最小必需的现货交易和账户读取权限。
- `.env` 只能由操作者手动填写，禁止提交，禁止在聊天、日志、截图中展示 key、secret、签名或请求头。
- 首次实盘只允许极小金额、单轮、人工盯盘。`live-setup-check pass` 只表示可以申请执行一次 bounded live canary，不表示可以长期运行。
- 任何 open、partial、unknown、同步失败、权限错误、5xx、网络超时、余额异常、滑点异常，都必须停止扩大灰度。
- 当前自动化只允许 `binance / BTCUSDT / 4h` 这条已完成测试网闭环的主线继续推进。

## 生产密钥准备

在交易所生产环境创建新的 API key：

- 权限：允许读取账户，允许现货交易。
- 禁止：提现权限、通用资金划转权限、无范围的管理权限。
- 建议：绑定本机或部署机器 IP 白名单，记录 key 创建时间和负责人，定期轮换。

`.env` 准备和只读复核阶段的关键项如下，具体 key/secret 由操作者手动填写。这个阶段不允许实盘下单，所以自动交易仍然保持关闭：

```dotenv
KXIAN_MODE=live
KXIAN_EXCHANGE=binance
KXIAN_SYMBOL=BTCUSDT
KXIAN_INTERVAL=4h
KXIAN_USE_TESTNET=false
KXIAN_MARKET_DATA_SOURCE=exchange

KXIAN_ALLOW_LIVE=true
KXIAN_LIVE_DRY_RUN=true
KXIAN_ENABLE_LIVE_AUTOTRADE=false
KXIAN_LIVE_CONFIRMATION=
KXIAN_LIVE_CREDENTIALS_CONFIRMED=false
KXIAN_MAX_LIVE_ORDER_USDT=50
```

`KXIAN_LIVE_CREDENTIALS_CONFIRMED=true` 只能在确认“这是生产 key、不是测试网 key、提现已关闭、权限最小化、最好已绑定 IP”之后设置。

进入单轮 canary 前，才允许在最后确认窗口内临时切换为：

```dotenv
KXIAN_LIVE_DRY_RUN=false
KXIAN_ENABLE_LIVE_AUTOTRADE=true
KXIAN_LIVE_CONFIRMATION=LIVE:binance:BTCUSDT:4h
KXIAN_LIVE_CREDENTIALS_CONFIRMED=true
```

## 固定命令顺序

先确认测试网闭环仍然有效：

```powershell
kxian-bot launch-checklist --target testnet
```

通过标准：

```text
status=pass
phase=testnet_observed_ready_for_live_review
```

然后晋升 live profile。这个命令不下单，但会写入本地 profile 状态：

```powershell
kxian-bot promote-profile-to-live --updated-by <operator>
```

再跑只读实盘准入检查：

```powershell
kxian-bot live-setup-check --timeout-seconds 5
```

通过标准：

```text
status=pass
phase=ready_for_bounded_live_canary
will_submit_orders=false
use_testnet=false
```

随后复核 live checklist：

```powershell
kxian-bot launch-checklist --target live
```

通过标准：

```text
status=pass
phase=ready_for_bounded_live_loop
```

只有人工再次确认后，才允许执行一次小额单轮 canary。执行前必须逐项确认：

- 生产 key 已确认，不是测试网 key。
- 提现权限已关闭，权限最小化，最好已绑定 IP 白名单。
- `KXIAN_MAX_LIVE_ORDER_USDT <= 50`。
- 当前无挂单，`launch-checklist --target live` 通过。
- 有人盯盘，交易所网页已打开 BTCUSDT 当前委托和成交页面。
- 本次只执行 `--max-iterations 1`，不启动长期 loop。

```powershell
kxian-bot trade-loop --max-iterations 1 --sleep-seconds 0
```

单轮后立刻复核：

```powershell
kxian-bot account-balance
kxian-bot sync-fills
kxian-bot launch-checklist --target live
```

复核必须看到：

- open orders 为 0。
- `account-balance` 返回账户同步成功。
- `sync-fills` 返回成交同步成功。
- 最后订单状态为 `idle`、`filled`、`canceled` 或安全拒绝之一。
- `launch-checklist --target live` 仍然通过。

如果输出里出现 `exchange_order_id` 且状态不是明确 closed，需要继续：

```powershell
kxian-bot order-status --order-id <exchange_order_id>
kxian-bot cancel-order --order-id <exchange_order_id>
kxian-bot sync-fills
kxian-bot launch-checklist --target live
```

## 判定表

| 阶段 | 允许继续 | 必须停止 | 下一步动作 |
| --- | --- | --- | --- |
| 测试网复核 | `status=pass` 且 `phase=testnet_observed_ready_for_live_review` | 缺 profile、缺观察证据、open orders、endpoint 异常 | 回到测试网手册补证据 |
| live profile 晋升 | `promote-profile-to-live` 返回 `status=pass` | 来源 profile 缺失或证据不完整 | 不进入 live，先补 testnet profile |
| 只读实盘准入 | `live-setup-check` 返回 `status=pass`，`will_submit_orders=false` | 凭证缺失、生产 key 未确认、端点是 testnet、live checklist blocked、订单额度超过 50 USDT | 按 `next_steps` 修复后重跑 |
| live checklist | `status=pass` 且 `phase=ready_for_bounded_live_loop` | live 开关、preflight、open orders、profile 任一失败 | 不执行 canary，先清理状态 |
| 单轮 canary | 只跑 `--max-iterations 1`，订单最终 idle、filled、canceled 或安全拒绝，open orders 为 0 | open、partial、submitted 未清理，未知订单状态，非安全 rejected，账户或成交同步失败 | 查单、撤单、同步成交、重跑 checklist |
| 灰度扩大 | 连续小额运行稳定，无挂单，无同步失败，无异常错误 | 连续亏损、滑点异常、错误率上升、账户余额不符 | 暂停自动化，降低额度或回到测试网 |

## 初始风控阈值

首次实盘建议先按以下阈值填写并签字确认：

| 项目 | 初始建议值 | 操作者确认 |
| --- | --- | --- |
| 单笔最大金额 | `KXIAN_MAX_LIVE_ORDER_USDT <= 50` | 待填写 |
| 单日最大成交额 | 不超过 200 USDT | 待填写 |
| 单日最大亏损 | 不超过 20 USDT，且不得高于账户可承受亏损 | 待填写 |
| 连续亏损暂停 | 连续 3 笔亏损即暂停 | 待填写 |
| 人工值守窗口 | canary 前后至少 30 分钟 | 待填写 |
| 回退负责人 | 必须明确到人 | 待填写 |

## 回退流程

出现异常时先让自动交易失效：

```dotenv
KXIAN_ENABLE_LIVE_AUTOTRADE=false
KXIAN_LIVE_DRY_RUN=true
```

然后执行：

```powershell
kxian-bot pause --reason live_guardrail_triggered --updated-by <operator>
kxian-bot order-status --order-id <exchange_order_id>
kxian-bot cancel-order --order-id <exchange_order_id>
kxian-bot sync-fills
kxian-bot account-balance
kxian-bot launch-checklist --target live
```

如果没有 `exchange_order_id`，先查交易所网页端的 BTCUSDT 当前委托，再决定是否手动撤单。不要通过反复启动 loop 来“碰运气”恢复状态。

## 正式投入使用标准

满足以下条件前，都只能算灰度，不算正式长期自动交易：

- 测试网最终 checklist 通过，且 live profile 晋升成功。
- `live-setup-check` 和 `launch-checklist --target live` 都通过。
- 至少一次极小金额单轮 canary 完成，订单生命周期可解释，open orders 为 0。
- `sync-fills`、`account-balance` 正常，SQLite 记录和交易所状态一致。
- 连续 1 到 2 周小仓位低频观察无门禁失败、无未知订单、无异常滑点、无同步失败。
- 明确了每日最大亏损、最大成交额、连续亏损暂停阈值、人工值守窗口和回退负责人。
- 上述初始风控阈值已填写、复核并执行过至少一次回退演练。

## 后续优化建议

- 增加 live 证据包导出，但必须脱敏且不保存签名、请求头、key 或 secret。
- Dashboard 增加实盘准入步骤条，只显示 boolean 和状态，不展示任何密钥内容。
- 增加浏览器级 Dashboard 自动化测试，覆盖按钮反馈、失败原因固定展示和只读按钮说明。
- 增加告警通知：循环心跳、open orders、fill sync、account sync、连续失败、余额异常。
- 增加不可变审计导出和 secret scan，部署前自动阻断 `.env` 与敏感字段泄露。
